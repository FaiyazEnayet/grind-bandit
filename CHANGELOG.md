# Changelog

## [Unreleased]

### Added
- Versioned state schema with a persisted migration path (`src/grindbandit/state.py`, `src/grindbandit/cli.py`, `docs/state-schema.md`). State files now record `schema_version` (current: 1); files written before versions existed count as version 0. Loads still migrate in memory only and never touch the file, but `grind-bandit migrate [--path PATH]` writes the migrated state back after copying the exact original bytes to `<path>.v<from>.bak` (written once; an existing backup is left alone so the earliest pre-migration copy is kept). Migrating a current file is a no-op; a file from a newer version is refused rather than silently downgraded. Migration invents no history: old log entries gain no attempt id or linkage, and no recommendations or quiz records are fabricated. The old-format example state at `tests/fixtures/state-v0-example.json` (three scripted attempts on real bank problems, values computed by the engine) migrates deterministically under these rules, and the demo-data builder's version 0 shaped state migrates the same way.
- Model documentation with worked numerical examples (`docs/model.md`). Mastery (Beta-Bernoulli with 30-day forgetting), the model-derived reward, the five context features, the Thompson sampling posterior update, eligibility and spaced review, and delayed quizzes are each documented with exact numbers reproduced by regression tests: ten solves then ninety idle days gives mastery 0.6923 and a failure right after gives 0.5294; a solve on a fresh topic rewards +1/6 and a failure -1/6; the fresh context for problem 28 is [0.5, 0.5, 0.5, 1.0, 1.0]; one observation moves the posterior mean to [0.02924, 0.02924, 0.02924, 0.05848, 0.05848]; seed 7 draws theta [0.001230, 0.298746, -0.274138, -0.890592, -0.454671].
- Precise attempt/recommendation lineage (`src/grindbandit/state.py`, `src/grindbandit/cli.py`). Every logged attempt now carries its own immutable `attempt_id`, and delayed quiz records name that exact attempt as `source_attempt_id`, so two attempts on the same problem never alias one source. The `log` command accepts `--recommendation-id`: the id is validated before anything is written and rejected when it is unknown, selected a different problem, is stale (a newer recommendation exists), or was already taken up by an earlier attempt. Without the flag, a link is only inferred from the globally latest recommendation when it is recent (within a day), unconsumed, and selected the logged problem, and the entry records it as `linkage_method: inferred`; explicit links record `linkage_method: explicit`, and a manually chosen attempt stays unlinked. Linked entries also carry a `recommendation_status` (exposed / accepted) where known. Nothing is fabricated for historical entries: state files written before this change load unchanged, their attempts gain no id or linkage retroactively, and their quizzes gain no source attempt id. Linkage metadata is bookkeeping only and never feeds mastery, the bandit posterior, or the model-derived reward; the demo-data builder passes deterministic attempt ids so its seeded history stays reproducible.
- Delayed quiz timing and assignment records (`src/grindbandit/state.py`, `src/grindbandit/cli.py`). Each quiz record now carries an `assignment` block: whether the problem was novel (never attempted, never assigned as a quiz), how many times it had been assigned before, and whether the topic's unused pool was exhausted, in which case the schedule message and the record both state that the assignment is a reuse. Each recorded outcome now stores the actual delay in seconds and an early / on-time / late status next to the solved flag and timestamp, and `stats` lists recorded outcomes with their timing alongside the pending quizzes (outcomes recorded before this change, which have no timing, are reported as such).
- Explicit eligibility policy and spaced-review resurfacing (`src/grindbandit/cli.py`, `src/grindbandit/bandit.py`, `scripts/common.py`). Candidate selection used to drop every ever-solved problem permanently, and when nothing remained it silently fell back to the full bank and reported that the user had solved every problem in the bank, which was false whenever unsolved problems were simply inside the one-day attempt cooldown. `cli.assess_eligibility` now classifies every problem in the bank with a deterministic reason: new_practice or due_review when eligible, cooldown_new_practice or review_cooldown when not. A solved problem resurfaces as a due review once the review interval (state config `review_interval_days`, default 7 days) has elapsed since its last attempt; the interval is a configurable starting heuristic, not a validated optimum. When no problem is eligible, `next` prints an explicit nothing-eligible message and appends no recommendation record instead of fabricating a pick. Recommendation records now carry a `policy` block with the review interval, the attempt cooldown, the feature version, and the eligibility entry for every problem in the bank, and each candidate carries its eligibility class and reason, so the logged eligible set can be checked against the policy. The demo-data helper in `scripts/common.py` follows the same policy and returns no pick when nothing is eligible.
- Context feature version `context-v2` (`src/grindbandit/bandit.py`). The recency feature now measures days since the least recently practiced topic on the problem, with never-practiced topics counting as the full 30-day cap: an untouched topic is the stalest signal a problem can carry. The context-v1 layout (most recent practice across topics, unseen topics ignored) is preserved as `bandit.context_v1`, and `bandit.replay_selection` dispatches v1 records to the preserved `replay_selection_v1` path, so records logged under either version replay to their logged picks.

### Fixed
- State saves are now atomic, validated, and serialized (`src/grindbandit/state.py`). A save writes to a temporary file in the same directory and moves it over the old file, so an interrupted serialization leaves the prior file readable instead of a partial file. A save takes an exclusive lock on a `<path>.lock` file first and fails with an explicit conflict when another process holds it, instead of silently overwriting that process's work. Loads validate the state shape and reject a wrongly shaped file with a named error; state files written before a top-level key existed gain that key with its empty default on load, deterministically and without changing the file on disk. Saving to a bare filename now works in the current directory. Added regression tests: basename round trip, interrupted save, contended save, sequential saves retaining both attempts, wrong-shape rejection, and deterministic migration.
- Delayed quiz outcomes could be recorded before the quiz came due (`src/grindbandit/state.py`, `src/grindbandit/cli.py`). A result stored minutes after scheduling never measured retention after the 3-day delay, yet it sat in the store indistinguishable from a real delayed outcome. `record_delayed_outcome` now rejects a pre-due outcome by default, and the `quiz` command refuses with the due date; `grind-bandit quiz <id> solved|failed --early` is the explicit override, and the outcome is marked early. Outcomes remain observational: recording one still changes mastery, the bandit posterior, problem records, recommendations, and the attempt log by exactly zero.
- Delayed quiz problems repeated while unused problems remained (`src/grindbandit/state.py`). The chooser only avoided problems with a recorded attempt, so the same problem could be handed out as a quiz again and again while never-attempted problems on the topic sat unused. Selection is now deterministic by tier: novel problems first (never attempted, never assigned), then assigned-but-unattempted, then attempted, lowest id inside a tier.
- Recommendation explanations now match the actual sampled draw (`src/grindbandit/bandit.py`). The old explanation derived its driver claim from the posterior mean while selection used a sampled theta, so it could credit a factor that did not drive the realized draw. The logged recommendation record now carries a sampled explanation: per-feature sampled contributions that sum with the intercept to the logged sampled score, the driver equal to the largest sampled contribution, and score uncertainty from 10,000 posterior resamples with the seed recorded. Picks made while the posterior score spread is still wide are labeled exploration, and uncertainty is reported as a model estimate, never as observed proficiency. The `next` command prints the logged explanation lines, and the demo-data helper passes its sampled theta to the explanation instead of recomputing from the mean.
## [v1.2.0] - 2026-10-30
### Docs
- Centered the README header: uniform dark badge labels and three action buttons in the dashboard palette (Open Dashboard, Explore Method, Run Locally).

### Added
- Recommendation logging (`src/grindbandit/bandit.py`, `state.py`, `cli.py`). Every `next` pick now appends a self-contained record to the state file: feature version (`context-v1`), the RNG seed used for the Thompson draw, the posterior and per-topic snapshot, and the full candidate set with context vectors and Monte Carlo selection probability estimates (10,000 posterior resamples on a separate RNG stream, add-one smoothed). `bandit.replay_selection` reconstructs the pick from the record alone, and tests pin that the replay matches the logged selection, before and after a JSON round trip.
- Attempt entries link back to the recommendation that selected the problem (`recommendation_id`) and label the reward as model-derived (`reward_kind: model_derived_mastery_change`); the `log` output uses the same wording.
- Delayed transfer quizzes. Logging an attempt schedules a quiz on the attempt's weakest topic with a different problem, due in 3 days. The new `quiz` command records the outcome into a separate `delayed_quizzes` store; outcomes never change mastery, the bandit posterior, or rewards, and `stats` lists pending quizzes. State files written before this change keep working.

## [v1.1.0] - 2026-10-18
### Fixed
- Forgetting no longer revives on update (`src/grindbandit/mastery.py`). `update` incremented raw counts and reset the decay clock, so after ten successes and 90 idle days (mastery 0.6923) a single failure raised modeled mastery to 0.8462 by resurrecting all the decayed successes. `update` now persists the decayed effective counts at the update time *before* adding the new observation; the raw attempt history stays intact in the append-only log. `replay` accepts the configured half-life so the weekly review reconstructs with the same decay as live mastery. Added regression tests: a failure after decay cannot raise the posterior mean, stored counts are decayed before the new observation lands, and incremental updates agree with chronological log replay across gaps and half-lives.
